## 2. Interface

```python
class PingRunner(Protocol):
    def run(
        self,
        replay_input: dict[str, object],
        *,
        test_id: UUID,
        project_id: UUID,
        source_device_id: UUID,
        destination_device_id: UUID,
    ) -> dict[str, object]: ...
```

- **Input:** exactly the verified output of `app.db.snapshot.replay_input(snapshot)` plus the four command identities accepted by the API. No other snapshot field, database row, request object or current project state is read.
- **Output:** one complete, immutable TASK-05 `PingTestResult` document (`contract_version = schema_version = "1.0.0"`, `lifecycle = "CLOSED"`).
- **Sync/async:** synchronous. No queue is added to the API layer; the deterministic virtual `EventQueue` is inside the engine only.
- **Purity:** no database writes, no topology mutation, no wall-clock/random input. Engine files may not import `app.db`, `app.modules`, `app.core`, FastAPI, SQLAlchemy, psycopg or torch. The existing boundary test remains authoritative.

## 3. Snapshot isolation

`replay_input()` verifies the stored digest and now returns a `deepcopy` of `configuration_json`. This is required so the runner can never observe or create aliasing to the stored snapshot. The end-to-end test mutates a returned projection and asserts the snapshot is unchanged.

## 4. ICMP identity

- One identifier per run: `DEFAULT_ICMP_IDENTIFIER = 1234` for all four requests.
- The identifier is a simulation constant, not derived from UUIDs, wall-clock time or request counters.
- `RequestCorrelation.test_id` is set to the identifier because that is the comparison key used by the frozen `EchoReplyCorrelator`; the logical UUID `test_id` appears only in the result identity fields.
- Sequence values are `1..4`.

## 5. Evidence phase map

| Phase | Name | Emitted kinds |
|---|---|---|
| `10` | Control | request start is internal; no wire event |
| `20` | Routing | `ROUTE_SELECTED`, `ROUTE_FAILED` |
| `30` | ARP | `ARP_REQUEST`, `ARP_REPLY`, `ARP_RESOLUTION` |
| `40` | Datapath | `FRAME_TX`, `FRAME_ARRIVED` (plus `FRAME_DROPPED`, `DEVICE_PROCESSED` where applicable) |
| `50` | Failure / limit | `ICMP_ECHO_TIMEOUT`, `ICMP_ERROR_*`, `EXECUTION_LIMIT_REACHED`, `PENDING_EVENTS_CANCELLED` |
| `60` | Observation | `ICMP_ECHO_EMITTED`, `ICMP_ECHO_MATCHED`, `REQUEST_FINALIZED`, `TEST_FINALIZED`, `OBSERVATION_CLOSED`, `LOCAL_ECHO_PROCESSED` |

Only frozen schema event kinds are emitted; `TEST_STARTED` is not used. The assembler validates the enum but never invents phase semantics. Queue indices are reassigned from 1 because the TASK-03 queue starts at 0 while the TASK-05 schema requires ≥ 1.

## 6. Evidence derivation rules

- **Frame/packet ids:** generated by per-run deterministic counters and carried explicitly in scheduled arrivals; slotted `EthernetFrame` objects are never mutated.
- **Hops:** only `FRAME_TX`/`FRAME_ARRIVAL` pairs sharing frame id, direction and connection id become physical hop evidence. No `LOCAL` hops; self-ping has empty `hop_evidence`.
- **Diagnostics:** at most one primary per request. Success has no primary and no RTT conflict; non-success has no match/RTT. Codes come from the frozen `DiagnosticCode` vocabulary.
- **Timings:** `deadline = started + 1_000_000_000`; RTT = matched finalization − emission; non-overlapping attempts; test finalization/closure never precede request finalizations.
- **Budgets:** TASK-03 defaults (`REQUEST_EVENT_BUDGET = 10_000`, `TEST_EVENT_BUDGET = 40_000`, `BRANCH_TRAVERSAL_LIMIT = 128`). Exhaustion produces `execution_status = INCOMPLETE`, `observation_status = NOT_STARTED`, `aggregate_outcome = null`, and `REQUEST_EVENT_BUDGET_EXHAUSTED` primaries rather than a partial or fabricated success.

## 7. Caller responsibilities (step 7, not yet implemented)

- Validate the command and snapshot before calling the runner; on invalid replay input translate `InvalidReplayInputError` to the unchanged outer envelope `{"error":{"code","message","details","request_id"}}`.
- Treat `ResultAssemblyError` as a fail-closed engine defect, never as a network outcome.
- Persist the returned document once with the approved project/simulation/state revision invariants; the engine performs no persistence.
- The API may not copy reference examples into results or overwrite outcomes.
